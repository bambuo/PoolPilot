# EXCHANGES.md — 交易所配置与凭据

「交易所」页登记各平台的连接信息与凭据。这份文档说明**凭据是怎么存的**、**密钥从哪来**，
以及**哪些保证它有、哪些没有**。

---

## 1. 一条配置里有什么

| 字段 | 说明 |
|---|---|
| 平台 | Lighter / 币安 / OKX / Gate。新建时**分两步**：第 1 步以卡片选平台，卡片按**中心化（CEX）/ 去中心化（DEX）分两组**，每张给出**平台图标**、形态胶囊与一句话简介；第 2 步填配置，顶部一张头卡显示正在配谁（图标 + 名称 + `code • 形态`，与库里那行对得上）。选定平台即带上它的接口地址与形态（**界面上不出现、不可改**），并把常见费率填好（可改）。编辑已有配置直接进第 2 步——平台已是定下来的事实 |
| 名称 | 同一个平台可以配多条（两个币安账号是常态），名字是区分它们的唯一依据。**必填**：为空时保存按钮按不下去，并在按钮上方写明原因 |
| 环境 | 主网。测试网**界面上不提供**：这四家的测试网地址没有实测过，而表单保存的是主网地址——给一个"测试网"开关等于承诺一件不成立的事。数据模型里仍保留该字段（卡片刻度会显示标记），接测试网时再补齐各家的测试网预设 |
| 地址 | **由平台预设决定，界面上完全不出现**：表单里没有它，卡片上也不显示，读取接口更不返回它。保存时按平台写入（下单与读账户都用它），更新时"不传即保持原值" |
| 费率 | 挂单 / 吃单（百分数）。**预填的是常见标准档，不校验** —— 实际档位因 VIP 等级而异，请自己核对 |
| 凭据 | API Key / Secret /（OKX 还要）Passphrase。**明文落库**（见下一节），界面只回显尾号。每个平台在这一栏给出**它自己的取 key 指引**（在哪儿创建、要留意什么；Lighter 那张还写明这把 key 目前没有消费方）。**Key 与 Secret 必须成对**：只填一个时保存按钮按不下去 |
| 开关 | 停用不删数据，只是标记"这条先别用" |

**同一个平台可以建多条**：身份是自增 Id，不是"平台标识"——后者只能存一条。

## 2. 凭据怎么存

**按原样保存，明文。没有加密。**

这里曾经做过一版"主密钥 + AES-256-GCM"，后来整套撤掉了。理由不是偷懒：

- 主密钥存在**同一个库里**（页面可设置的那一版），拿到库的人同时拿到密文与密钥——
  它防不住任何"拿到库"的场景。真正防得住的只有"密钥不在库里"（环境变量/密钥链），
  而那要求使用者先去配环境变量才能存凭据，徒增一道坎。
- 更糟的是**它看起来像有保护**。"已加密"这几个字会让人把有交易权限的密钥也贴进来，
  而实际风险与明文一样。**假象比明文危险**。

于是现在如实说明：

- 凭据以明文写入 `exchange_configs` 的 `ApiKey` / `ApiSecret` / `Passphrase` 三列。
- 界面仍**只回显尾号**、不提供查看入口——那是减少屏幕上的暴露面，与存储方式无关，别把它当加密。
- 界面与卡片上都写着"明文保存"，并提示**只放没有提现权限、最好也没有交易权限的密钥**。
- 想更安全：用只读或最小权限的 API key，并绑定 IP 白名单。那比任何本机加密都有用。

## 3. 数据

| 表 | 说明 |
|---|---|
| `exchange_configs` | 配置本体。凭据三列（`ApiKey` / `ApiSecret` / `Passphrase`）是**明文** |
| ~~`app_settings`~~ | 已删除：它只为存放加密主密钥而存在。密钥材料不该以任何形式留在库里，哪怕只是曾经放过它的容器 |

那两件事（三列改回本名、删掉 `app_settings`）在开发库上已经执行完毕，
相应的一次性迁移代码已按"代码只保留最新状态"移除——`DatabaseSchemaInitializer`

## 4. 谁在用它

**实盘跟单员。** 把配置绑定到一个实盘跟单员之后，系统就用它对**币安 U 本位永续**真实下单：
开仓、平仓、读账户与持仓。币安是执行侧唯一有实现的平台；OKX 与 Gate 只有合约目录（供标的映射
查询），Lighter 只有读取。

配置本身不会让任何东西开始交易——**要再建一个实盘跟单员订阅带单员**，才会按信号下单。
这句话也写在页面上，否则使用者会以为配好凭据就自动交易了。

## 5. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/exchanges` | 全部配置（无凭据字段） |
| POST | `/api/exchanges` | 新建。凭据可选；给了就按原样保存（明文） |
| PUT | `/api/exchanges/{id}` | 修改。凭据是**三态**（见下） |
| DELETE | `/api/exchanges/{id}` | 删除（连同密文） |
### 接口地址：读不到，也不会被改掉

接口地址不面向界面——表单里没有、卡片上不显示、`GET /api/exchanges` 也不返回。
因此更新时前端**拿不到旧值**，若把"不传"当成"清空"，保存一次改动就会把已存的地址抹掉，
而界面上完全看不出来（只有真去下单或读账户时才会以"地址为空"暴露）。

所以 `PUT` 对 `restBaseUrl` / `wsUrl` 的语义是：**不传（null）即保持原值**。
与凭据的三态不同，这里没有"清除"这一态——地址由平台预设决定，清除它没有用途。
（`POST` 时照常接受这两个字段，新建流程会把预设的地址一并提交。）

### 凭据的三态（PUT）

| 传什么 | 效果 |
|---|---|
| **不传这个键** | 保持原样 |
| **传空串** | 清除 |
| **传值** | 换成新的（存原值） |

少了"清除"这一态，贴错的 key 就永远删不掉。界面上对应"点『更换 / 清除』后留空保存"。

另外：**Key 与 Secret 必须成对**。只填一个会被拒绝——半份凭据调不通任何接口，
但卡片上会显示"已配置"，那种"看起来成功"的失败最难查。

## 6. 平台图标

四个平台的标识图随包走（`web/src/assets/exchanges/`），**不在运行时外链加载**：
各家的 CDN 会拦也会变（实测 Gate 的 `apple-touch-icon` 直接 403），
把界面上的图标交给别人的可用性不可接受。来源与原始尺寸记在该目录的 `README.md` 里，
用途仅限**指认平台**（配置卡片上标出"这是哪一家"）。

## 8. 实盘执行侧（币安 U 本位合约）

### 这一层现在长什么样（2026-10-13 起）

对接**统一走 CryptoClients.Net**（元包，MIT）。自研的 HMAC 签名、时间同步、限流、
WebSocket 重连与逐字段解析都撤了，交给库；本项目只留下三样东西：

- **业务口径**：标准交易对与平台合约代码的转换、只算有量的仓位、持仓模式取不到时不拦住看账户、
  合约目录"不按计价币过滤 / 只收两个永续命名空间"这类实测规则；
- **事件语义**：推送说"变了"、REST 说"是什么"；强平（原始订单类型是 `Liquidation`）与
  保证金不足必须显眼；重连之后上层要补一次账户状态；
- **错误透传**：交易所的错误码与文案原样带出。已用**假凭据实调**验证过——
  拿到的就是币安原文（`code -2014`、`API key format invalid`、HTTP 401），不是被翻译的一句描述。

两条随之而来的变化：

1. **接入地址不再由配置决定**（执行侧）。主网/测试网由库的 `BinanceEnvironment` 表达，
   配置里那两列地址（`RestBaseUrl`/`WsUrl`）对执行侧不再作数——它们仍存在、仍在界面上预填，
   但改它们不会改变下单打到哪里。`IsTestnet` 开关仍然有效。
2. **库没封装的地方共两处**（各有专门的类写明依据）：
   - `POST /fapi/v1/order/test`（币安 U 本位合约）：库只给了现货的 `PlaceTestOrder`，
     U 本位没有；它的 `RestApiClient.SendAsync` 是 protected，也没有自定义端点入口。
     这一条自己发——但用的是库的环境地址与已实测、有独立参考值锁住的签名（`BinanceSignature`），
     参数形状与下单共用同一个生成函数，两处不会漂移。
     **它是唯一能在不花钱的前提下证明"这单发得出去"的办法，所以留着，不因为"库没有"就删掉。**
   - **Lighter 的池分析面**（池枚举 / 净值序列 / 池的成交与挂单 / 盘口）：库的 Lighter 客户端
     只封了 `account_all`、`account_all_assets`、`user_stats` 三个频道与四条 REST 路径，
     池这一面它没有。明细见 `docs/LIGHTER-API-NOTES.md` §7.4（那张表就是"哪条走库、哪条走自研"的清单）。

**三家的合约目录现在都来自库**（Binance.Net / OKX.Net / GateIo.Net），各自的实测口径原样保留
（只收永续的两个命名空间、不按计价币过滤、反向合约不收、下架合约不收、传统金融按平台自己的分类判），
并有 **Live 契约测试**盯着——它们直接连公开接口，断言"库的模型 → 我们的口径"这一段没变味。
这套测试已经赚回一次：OKX 的传统金融判据一度拿的是上游 `category`（恒为 "1"）而不是 `instCategory`，
结果是"一个传统金融合约都没有"，被它当场逮住。

Lighter 那边的分法是：库覆盖到的读法（系统配置游标、账户快照、合约规格）做成**库客户端上的
C# 扩展成员**（`extension(ILighterRestClient client)`，见 `LighterClientExtensions`）；
库里没有的池面（枚举、净值序列、成交、挂单、盘口）自己发。**扩展方法只能碰公开成员**——
库的请求管线 `RestApiClient.SendAsync` 是 protected，公开的只有 `GetAuthenticationProvider`/`SetOptions`，
所以新增端点接不进库的管线，这不是取舍问题而是语言层面的边界。

### 一条硬约束：双向持仓模式

该账户实测是**双向持仓模式**（`dualSidePosition = true`），因此 `positionSide` 指的是
"要影响哪一侧的持仓"，**不是买卖方向**：

| 意图 | 方向 | positionSide |
|---|---|---|
| 开多 | BUY | LONG |
| **平多** | **SELL** | **LONG** |
| 开空 | SELL | SHORT |
| **平空** | **BUY** | **SHORT** |

从买卖方向推导 positionSide 会把"平多"写成"开空"——那是会开错方向的错误。
所以接口只接受**意图**（`open_long` / `close_long` / `open_short` / `close_short`），
不接受裸方向；四种组合在 `BrokerOrderRequest.FromIntent` 里逐一写死，并有测试锁住。
双向模式下**不能带 `reduceOnly`**（币安拒单），减仓靠上表的方向与 positionSide 组合表达。

### 规模口径

**标准跟单：比例复制**，不给名义额设人为上限——
目标名义额 = 池子名义额 × (本金 ÷ 池子权益)。风险因此被本金天然封顶（能亏的上限就是投进去的钱）。

拦住"下不出去的单"的是交易所自己的规格：最小下单量、最小名义额、可用保证金。
这些不是限额而是硬规则，所以本地会先算一遍并**如实记录跳过原因**（差多少、为什么），
而不是发出去让币安回一个 `-4164` 再回头猜。

⚠️ **小资金的算术现实**：账户里 5 USDT 时，比例复制出来的名义额通常只有几 USDT，
低于多数合约的最小名义额（实测 ETHUSDT 20、BTCUSDT 50；ENA/ZEC/PUMP 等为 5）。
也就是说小资金下大部分池子动作会被规格挡掉，只有池子里仓位较重的市场才跟得上。

### 跨场所标的映射（Lighter 市场 → 币安合约）

`GET /api/exchanges/{id}/symbol-map?pool={池账户索引}` 逐市场给出"能不能跟、为什么"。

**实测事实（2026-10-06）**：

| 事实 | 数据 |
|---|---|
| 币安合约分两个命名空间 | `PERPETUAL` 703 个（加密）、**`TRADIFI_PERPETUAL` 216 个**（股票/商品/指数） |
| 两者互不相交 | 撞名 0 个 |
| Lighter 市场 | 237 个 |
| FLEXIBLE POOL 可跟性 | **17/17 全部可跟**，其中 8 个走币安传统金融合约（SPCX/NVDA/META/PLTR/ORCL/ANTHROPIC/SNDK/CRWV） |

⚠️ **第一版实现漏了这一整类**：只筛了 `contractType == PERPETUAL`，于是得出"币安没有股票合约"的
错误结论。教训是筛选条件本身就是结论的一部分——把"我没查到"当成"不存在"之前，先确认筛选条件够宽。

**同名不等于同物，所以映射要过价格关**：两边价格比值超出 [1/3, 3] 就拒绝映射并记下原因。
实测这条检查既挡得住真陷阱（Lighter `US500` 7790 点 vs 币安 `SPYUSDT` 776.9，是"指数点位"与
"ETF 份额"两个不同工具），也不会误伤（Lighter `SPX` 与币安 `SPXUSDT` 都是 0.43 —— 两边都是
SPX6900 那个 meme 币，同名同物）。

**需要人工别名的只有"同一个物、不同名字"**，全部经价格验证后登记（值必须是 baseAsset）：

| Lighter | 币安 baseAsset | 合约 | 价格对照 |
|---|---|---|---|
| `WTI` | `CL` | CLUSDT | 87.947 vs 87.98 |
| `BRENTOIL` | `BZ` | BZUSDT | 98.97 vs 99.06 |
| `XCU` | `COPPER` | COPPERUSDT | 6.6791 vs 6.668 |

别名只**追加**候选、不挤掉同名候选；价格检查照旧执行——哪天这对不再同物，检查会把它挡下来。

**能映射 ≠ 跟得动**：币安各合约的最小名义额不同（实测 ENA/ZEC/NVDA 等为 5 USDT，
ETHUSDT 20、**BTCUSDT 50**）。按比例复制算出来的名义额低于该合约门槛时，本地就会记成"未跟上"。

## 用户的实时数据：WebSocket 路由路径（2026-10-06 实测订正）

> 这一节记录的是**上游的事实**。自 2026-10-13 起连接与路径由 CryptoClients.Net 负责，
> 我们不再自己拼这些地址——留着它是因为它是"为什么当时的探针会给出错误结论"的原始记录，
> 也是将来怀疑"是不是路径又变了"时的第一份对照材料。

币安在 2026 年把合约 WebSocket 拆成了**路由路径**，旧的 `wss://fstream.binance.com/ws/<stream>`
已于 **2026-04-23 永久退役**：

| 用途 | 现在要连的地址 | 实测 |
|---|---|---|
| 高频公开（`@depth`） | `wss://fstream.binance.com/public/ws/<stream>` | 56 帧 / 6 秒 |
| 常规行情（`@ticker`、`@markPrice`） | `wss://fstream.binance.com/market/ws/<stream>` | 3 帧 / 6 秒 |
| 常规行情（组合流） | `wss://fstream.binance.com/market/stream?streams=<s1>/<s2>` | 3 帧 / 6 秒 |
| **用户数据流** | `wss://fstream.binance.com/private/ws?listenKey=<listenKey>` | 真实订单事件 ✓ |
| 已退役的旧路径 | `wss://fstream.binance.com/ws/<listenKey>` | 握手 101 通过、**0 帧** |

**退役的表现是"静默"**：连接握手成功（101），然后**一条数据都不来，也不报错、不断开**。
所以旧路径上的失败与"账户安静没有事件"长得一模一样。

⚠️ 本项目在这上面栽过一次，值得记住的是**误判的方向**：先用旧路径的公开行情当探针，
探针收不到帧，于是得出"这台机器到币安行情主机的链路被网络挡住了"——一个听起来很有道理、
实际完全错误的结论（同一台机器上现货 WS、REST、Lighter WS 都正常，正好"印证"了那个猜测）。
**探针走错路径比没有探针更糟：它会把一个确定的错误结论说得理直气壮。**
走到 `/market` 路由上，探针立刻恢复正常。

其他仍然成立的细节（同一批实测）：

- `listenKey` 的**生命周期接口没变**：`POST` 建、`PUT` 续期（60 分钟寿命，25 分钟续一次足够）、
  `DELETE` 关闭，三条都还是 200。变的是**连接用的路径**，不是会话管理。
- `?events=ORDER_TRADE_UPDATE,ACCOUNT_UPDATE` 这种过滤参数在 `/private/ws` 上会被拒（HTTP 400）——
  不带它即可，默认就推全部账户事件。
- 事件载荷与旧的一模一样（`ACCOUNT_UPDATE`、`ORDER_TRADE_UPDATE`、`MARGIN_CALL`、
  `ACCOUNT_CONFIG_UPDATE`、`listenKeyExpired`），所以解析代码不用改。
- 强平走的是 `ORDER_TRADE_UPDATE`（`o.o = "LIQUIDATION"`），不是单独的事件类型。
